# Температурный комфорт {#temperature-comfort}

**Вопрос:** насколько измерение 24 °C соответствует понятиям *Comfort* и *Warm*? Самостоятельный пример в [быстром старте](../quick-start.md) показывает создание шкалы и вычисление обеих степеней.

На нисходящей стороне `Triangle(16, 22, 28)` степень комфорта равна

$$
\mu_{\mathrm{Comfort}}(24)=\frac{28-24}{28-22}=\frac{2}{3}.
$$


Первая половина квадратичного плеча даёт

$$
\mu_{\mathrm{Warm}}(24)=2\left(\frac{24-22}{30-22}\right)^2=\frac{1}{8}.
$$


[![Температурная модель и вычисленные степени принадлежности](../../en/assets/figures/temperature.svg)](../../en/assets/figures/temperature.svg)

Максимальная степень выбирает *Comfort*. Результат не означает вероятность комфорта 66,7%. Обе степени описывают одно измерение согласно двум определениям. Их сумма не обязана равняться единице.

**Инженерная проверка:** универсальное множество включает обе границы, поэтому принадлежность при 0 и 40 °C определена. Координата вне него вызывает ошибку области определения. В минимальной шкале есть низкотемпературный пробел: при температуре не выше 16 °C обе степени равны нулю. Если требуется полное покрытие, добавьте терм холода и проверьте шкалу.

**Применение в проекте:** сохраняйте весь вектор принадлежностей для панели наблюдения или последующего вычисления по выбранным правилам; используйте `selectedTerms`, когда полезна одна метка. Не теряйте информацию о слабой степени у победившего терма. Следующий сценарий показывает отказ от классификации.

```bash
python -I examples/guide.py --scenario temperature
```
