## Measured results and interpretation

The installed [scalar comparison](../performance/installed-scalar-comparison.md) uses CPython 3.14.8, Linux x86-64 and an Intel Xeon Platinum 8573C. Seven alternating baseline/candidate pairs cover 28 mathematical workloads plus process startup and package import. All independent membership/operator references use absolute tolerance `1e-12`, centroid references `1e-10`, and relative tolerance zero. Both untimed preflights and all 14 measured workers passed; cross-version observations agreed. Each environment contained only its installed FuzzyRoutines distribution.

| Example workload                  | 2.0.0 median / minimum / IQR, µs       | 2.1.0 median / minimum / IQR, µs        |
| ---                               | ---                                    | ---                                     |
| Universal-scale lookup            | 5.719162 / 3.730991 / 2.521044         | 5.228156 / 3.855152 / 2.439385          |
| Hyperbolic centroid recalculation | 2711.358000 / 2024.418100 / 235.799800 | 3477.225000 / 2044.790700 / 3465.095500 |

Results are mixed. Process-startup medians also varied, from 45.417 ms to 37.071 ms despite the same interpreter. Large IQRs and the shared host prevent a causal regression or general speedup claim. Full minimum/median/IQR tables and raw elapsed times, counts and rates remain in the report; no performance threshold was used as a pass/fail gate.

The installed [NumPy study](../performance/installed-batch-results.md) uses NumPy 2.3.5 and the same candidate wheel for scalar and batch calls. All 24 synthetic combinations passed grade parity at absolute `1e-12`, relative zero, with maximum observed error `1.1102230246251565e-16`; selected/tied masks matched exactly. At one coordinate NumPy was slower throughout. At 10,000 coordinates, full scale classification measured scalar/NumPy median ratios of 49.07× for list inputs and 72.99× for prepared arrays. These are separate workloads, not interchangeable speed figures or a universal switching threshold. Memory, fresh-process import and optional-dependency costs are recorded separately.

The four batch replay combinations group **30 actual public upstream test inputs**, 17 `RiskLong` and 13 `RiskShort`, rather than observed production batches. Grades/masks and independently authored expected labels/percentages matched; scalar/NumPy ratios ranged from 0.61× to 1.01×, with no consistent advantage for these small groups. Separately, the migration CLI checked **27 synthetic public-boundary cases** after scalar timing. These two fixtures are distinct and must not be presented as private application or production validation.

## Limits and deliberate exclusions

The benchmark host was shared; other project benchmarks were paused, but exclusive hardware was not claimed. The pinned public consumer fixtures exercise declared scale boundaries and upstream test inputs, not an entire application, trading backtest or production trace. **Private FMA projects and the robot remain unverified.** Their adoption of 2.1 requires their own installed-package integration checks. The [consumer migration record](../migration/consumer-scale-boundary.md) distinguishes preserved labels from the historical centroid correction.

Membership grades are not probabilities, and centroid representatives are not learned network weights. Fixed fuzzy encodings can lose information. Neural comparisons use a bounded synthetic task and establish no general accuracy advantage. [ADR-0020](../adr/0020-differentiable-sugeno-feasibility.md) records **no-go for a public tensor backend in 2.1**; the optional research prototype is not a supported trainable API or an implementation of ANFIS hybrid training.

Public convexity queries, symmetric-difference semantics and free-threaded support remain deferred. Inference vectorization, arbitrary-callable batching and automatic backend switching are also outside the accepted scope. This handoff adds no new feature promises.
